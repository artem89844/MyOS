# MyOS — результат повторной сборки и проверки

Дата проверки: 15 ноября 2026 г.
Проверялся отдельный распакованный экземпляр `MyOS-fixed-4-bugs.zip`; исходный ZIP не изменялся.

## Результат сборки

- `make clean` — выполнено.
- `make -j2` — успешно, ошибок и предупреждений компилятора не обнаружено.
- `make check` — успешно.
- ELF: 32-bit, little-endian, Intel 80386, статически слинкованное исполняемое ядро.
- Entry point: `0x10001c`.
- Multiboot v1 header: найден на файловом смещении `0x1000`, flags `0x00000007`, checksum верна.
- Новый `kernel.bin`: 35 744 байта.
- Новый `kernel.raw`: 26 976 байт.
- `iso/boot/kernel.bin` обновлён копией свежесобранного `kernel.bin`; проверено совпадение содержимого.

Подробные логи находятся в каталоге `verification/`.

## Статическая проверка исправлений

- GDT устанавливается в `boot.S`; селекторы согласованы: код `0x08`, данные `0x10`, IDT использует селектор кода `0x08`.
- Heap использует Multiboot memory map и `mem_upper` fallback.
- ATA API содержит только чтение; реализация записи отсутствует.
- IRQ handler не вызывает отрисовку; очередь событий обрабатывается в главном цикле, где выполняется перерисовка.
- Все проверки `verification/static_audit.py` прошли.

## Почему ISO и запуск в эмуляторе не выполнены

В данной среде отсутствуют все необходимые инструменты:

- `grub-mkrescue` — отсутствует; команда `make iso` остановилась с точной ошибкой `ERROR: grub-mkrescue not found`.
- `xorriso` — отсутствует.
- QEMU (`qemu-system-i386` и `qemu-system-x86_64`) — отсутствует.

Также не обнаружены альтернативы `grub2-mkrescue`, `genisoimage`, `mkisofs` и `bochs`.

Поэтому новый загрузочный ISO не создан, а запуск ядра до рабочего стола и поведение интерфейса в VM не подтверждены. Существующие ISO в проекте оставлены без изменений и не выдаются за свежесобранные.

## Безопасность диска

Не запускались тесты записи на физические диски. ATA-драйвер проекта оставлен в режиме только чтения.

## Как завершить проверку на машине с установленными инструментами

Из каталога `MyOS` выполнить:

```sh
make clean
make -j2
make check
make iso
qemu-system-i386 -m 256M -cdrom myos-new.iso -boot d -no-reboot -no-shutdown
```

В QEMU не подключать реальные блочные устройства хоста. Для тестирования записи (если она когда-либо будет реализована) использовать только отдельный временный образ диска.
